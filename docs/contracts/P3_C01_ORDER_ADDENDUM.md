# P3-C01 implementation addendum — R04/R05 dine-in

23/10/2026. Additive implementation notes; canonical DTO/error enums and endpoint names in API_CONTRACT_V1/types.ts are unchanged.

- R04 POST and replay both return201 `ApiResponse<OrderDetail>`. Dine-in only in C01; takeaway returns409 INVALID_STATE_TRANSITION with details.field=orderType and no order/ticket/payment. Phase4 must explicitly extend schema and implement pending-payment behavior before enabling it.
- R05 default returns200 OrderDetail to live same-session guests. includePickup=true retains canonical wrapper; for dine-in pickup=null and the creating browser/access binding is required by buyer-only projection. No owner fallback, no read-by-key public endpoint.
- Strict CreateOrderV1Input requires menuRevision and nullable notes. UUID inputs normalized lowercase; option IDs distinct after normalization then sorted; notes trim/remove controls; line order retained in fingerprint. Unrecognized client context/prices/totals rejected400. Body64KiB;100 lines,qty1–99,50 optional additive option IDs/line,note<=500.
- Error names use existing enums. Option membership/availability and safe-arithmetic failure422 VALIDATION_ERROR; unavailable item/category409 OUT_OF_STOCK before stale revision409 PRICE_CHANGED. Zero VND dine-in is accepted with unpaid session payment projection, no provider call, following existing nonnegative money contract. No required/exclusive option policy is added.
- Idempotency unique(store_id,client_request_id), bound creating browser+guest-access and canonical command fingerprint.201 replay preserves original command snapshot, even after later order state/menu/store/checkout changes, but requires live nonrevoked grant/code/session. Closed/expired410, another browser403, changed normalized payload409 DUPLICATE_REQUEST_CONFLICT. New create limit10/min/browser/store; replay bypasses create rate, R05 limit60/min/browser/order.
- Session grant already authorizes dine-in tracking by contract; no new broader order grant/TTL. HttpOnly cookie stays Phase2 opaque browser transport. Missing POST cookie401, unverified table403, cross-table/store denied; GET outside-session404.
- Transaction gate store FOR NO KEY UPDATE → table SHARE → QR SHARE → session UPDATE, preceded by command advisory lock. The store lock mode deliberately permits FK KEY SHARE during session-close while excluding concurrent menu/settings writers. See regression test and handoff before implementing settlement/owner transitions.
- Current diner payment projection is unpaid because settlement is Phase5. No fake ledger or paid state is inferred from closed/completed. Protected replay records contain private accepted snapshot; audit/outbox contain metadata only and no notes/credentials. Outbox is durable but publishing/realtime is not implemented.
- Phase2 cart storage omits note text. Exact replay across reload needs immutable command restoration; automatic persistence of raw notes/PII has not been authorized by this addendum. Do not reconstruct changed input under the old key or issue a new command while old result is unknown.
